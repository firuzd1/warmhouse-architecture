# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**
- Пользователи могут включать/выключать отопление
- Можно задать нужную температуру в доме
- Сервер сам опрашивает датчикии когда нужны данные

**Мониторинг температуры:**
- Пользователь видит текущую температуру по комнатам
- Данные берутся с датчиков через запросы к temperature-api
- Можно запросить температуру по названию комнаты или по id датчика

### 2. Анализ архитектуры монолитного приложения

- Написано на Go
- База данных PostgreSQL
- Код разделён на слои: handlers, services, models, db
- Всё работает синхронно, никаких очередей и брокеров нет
- temperature-api это отдельный сервис, монолит дёргает его по http
- Конфигурация через env переменные
- Докерфайл есть, docker-compose тоже

### 3. Определение доменов и границ контекстов

**Домен: управление устройствами**
- поддомен датчиков
    - контекст регистрации датчиков
    - контекст телеметрии

**Домен: управление отоплением**
- поддомен климата
    - контекст управления реле
    - контекст мониторинга температуры

**Домен: пользователи** (в текущей версии не реализован)
- аутентификация
- управление аккаунтом

**Домен: умный дом** (целевое состояние)
- освещение
- ворота
- видеонаблюдение
- сценарии автоматизации

### 4. Проблемы монолитного решения

- Масштабировать можно только всё приложение целиком, отдельные
  части — нельзя
- Если что-то падает — падает всё
- Добавить новый тип устройства сложно, надо лезть в монолит
- Пользователь не может сам подключить датчик, нужен специалист
- Поддерживается только temperature, других типов устройств нет
- Всё синхронно, при большом кол-ве устройств будут проблемы
- Нет авторизации и управления пользователями вообще

# Задание 4. Создание и документирование API

### 1. Тип API

Будем использовать REST API. Выбрал его потому что:
- простой и понятный, все разработчики знают как с ним работать
- хорошо подходит для CRUD операций которых у нас большинство
- легко документировать через Swagger/OpenAPI
- клиенты могут быть любые — мобилка, веб, другие сервисы
